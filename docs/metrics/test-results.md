## 5. Передавання фотографій у S3b

- Передано: **75 із 75** фотографій.
- Формат: **160×120, RGB565**.
- Розмір одного кадру: **38 400 байтів**.
- Сумарний обсяг піксельних даних: **2 880 000 байтів** (без урахування протокольних заголовків).
- Параметри UART: **115200 baud, 8-N-1**.
- Для фото id=18 журнал зафіксував відновлення після сторонніх байтів: **289 байтів відкинуто**, **0 повторних передавань чанків**.
- `photo selftest`: **PASS**.
- UART counters: `rx_overflow=0`, `tx_drop=0`, `tx_queue_overflow=0`, `tx_start_error=0`, `rx_restart_error=0`.

Оціночна нижня межа часу передавання лише 2 880 000 байтів по UART 115200 baud у форматі 8-N-1 становить близько 250 с: кожен байт передається 10 бітами, тому `2 880 000 × 10 / 115 200 ≈ 250 с`. Це теоретична оцінка без протокольних накладних витрат і пауз; її не слід подавати як фактично виміряний час передавання.

## 6. Теоретичні оцінки, які можна зробити з наявних даних

- **UART для фото:** 75 кадрів × 38 400 байтів = 2 880 000 байтів. Для 115200 baud, 8-N-1 один байт займає 10 біт, тому нижня межа передавання без протокольних накладних витрат становить `2 880 000 × 10 / 115 200 ≈ 250 с`. Це оцінка payload-only, а не виміряний час.
- **Час формування кадру OV7670:** не розраховано. У startup log є XCLK=12,5 MHz і розмір кадру, але немає достатніх даних про фактичний PCLK, режим синхронізації, blanking та кадрову частоту. Не можна підставляти XCLK замість PCLK.
- **Час стирання W25Q64:** не розраховано. Для цього потрібні підтверджений тип операції (sector/block/chip erase), параметри datasheet для конкретної операції та виміряний інтервал у прошивці/логічному аналізаторі. У наданих логах такого вимірювання немає.

## 7. Критерії оцінювання та обмеження даних

| Пункт                 | Що відомо                                                 | Чого бракує                                                                                                                                                  |
| --------------------- | --------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Min/avg/max           | У логах записані min/avg/max для циклу й задач.           | Не для всіх показників зручно витягнуто повний ряд; не всі percentiles.                                                                                      |
| 99-й перцентиль       | Не записаний у наданих логах.                             | Потрібно додати обчислення P99 у скрипт експорту/аналізу.                                                                                                    |
| Повтори сценаріїв     | По одному логу для S1, S2, S3a, S3b.                      | Щонайменше кілька незалежних повторів для оцінки розкиду.                                                                                                    |
| Порівняння з PRD      | Є функціональні вимоги FR-01…FR-15.                       | У PRD не наведено числових меж часу реакції/CPU load для зіставлення з максимальними метриками. Потрібно вказати критерії з методички, якщо вони там задані. |
| Breakpoint            | Максимальне навантаження сценаріїв зафіксовано.           | Не проводився систематичний пошук першої точки порушення вимоги.                                                                                             |
| Повна CPU utilization | `measured_work_load` оцінює лише інструментовані ділянки. | Потрібен повніший метод або чітке формулювання, що це оцінка instrumented workload.                                                                          |
